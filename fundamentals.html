DBMS · Operating Systems · Networks

These three subjects rarely get their own round at SDE-2, but they're exactly where a "does this person actually understand computers" probe shows up mid-interview — inside an HLD deep dive, a debugging story, or a Microsoft/Apple loop that still runs a dedicated CS fundamentals round. The bar here isn't textbook recall: it's being able to explain why an index speeds up a query, why a deadlock happens, or what actually happens between typing a URL and pixels on screen — in your own words, under follow-up pressure.

3 subjects DBMS · OS · CN 9 curated resources
01 — DBMS

Database Management Systems

The subject most likely to show up disguised as an HLD deep dive ("why did you pick this index?") rather than as its own round.

•Normalization: 1NF → BCNF — and, just as important, when to deliberately denormalize for read performance.
•Indexing: B-tree vs hash index, clustered vs non-clustered, composite index column order, covering indexes — and why an index can make writes slower.
•Transactions: ACID properties, isolation levels (Read Uncommitted → Serializable) and which anomalies each one prevents (dirty read, non-repeatable read, phantom read).
•Concurrency control: optimistic vs pessimistic locking, MVCC (how Postgres/MySQL InnoDB actually implement it).
•Joins & query execution: nested loop vs hash vs merge join, and reading an EXPLAIN plan.
•Storage engines: B-tree (Postgres/InnoDB) vs LSM-tree (Cassandra/RocksDB) — write-amplification vs read-amplification trade-offs, covered in more depth on the HLD page.

02 — Operating Systems

Processes, memory, concurrency

This is the theory behind the Java concurrency questions on the Java page — worth doing in this order: OS mental model first, then the JVM-specific implementation.

•Processes vs threads: what's shared (address space, file descriptors) vs private (stack, registers, PC) — and why context-switching a thread is cheaper.
•CPU scheduling: round robin, priority scheduling, multilevel feedback queues — and starvation as the failure mode to always mention.
•Memory management: paging vs segmentation, virtual memory, page replacement (LRU, Clock), thrashing.
•Deadlocks: the four Coffman conditions (mutual exclusion, hold-and-wait, no preemption, circular wait) — prevention breaks one of them; the Banker's Algorithm is avoidance, not prevention.
•Synchronization primitives: mutex vs semaphore vs monitor, the classic producer-consumer / dining-philosophers / readers-writers problems.
•IPC: pipes, message queues, shared memory, sockets — and when you'd reach for each.

Best OS resources

Read the concurrency chapters even if you skim the rest. 03 — Computer Networks

Protocols & the request lifecycle

"What happens when you type a URL and hit enter" is still asked directly — and it's also the backbone of every networking building block on the HLD page.

•OSI / TCP-IP model: know the layers well enough to place any protocol you're asked about correctly, on the spot.
•TCP vs UDP: three-way handshake, reliability/ordering guarantees, and when UDP's lack of guarantees is the right trade-off (video, gaming, DNS).
•HTTP evolution: HTTP/1.1 vs HTTP/2 (multiplexing, header compression) vs HTTP/3 (QUIC over UDP) — and why each version exists.
•TLS handshake: what a certificate actually proves, and roughly how the handshake establishes a shared key.
•DNS resolution: the full chain — browser cache → OS cache → recursive resolver → root → TLD → authoritative server.
•The full "type a URL" flow: DNS resolution → TCP handshake → TLS handshake (if HTTPS) → HTTP request/response → render — be ready to narrate all five steps without prompting.

Best networking resources

Free · Full book High Performance Browser Networking Ilya Grigorik's free O'Reilly book — TCP, UDP, TLS, HTTP/1.1 through HTTP/2, WebSocket, WebRTC. The most rigorous free resource on this list, staff-level depth. Free · Interview-framed Hello Interview — Networking Essentials The subset of networking that actually shows up in system design interviews, framed around the trade-offs interviewers probe rather than protocol trivia. Free · Classic walkthrough GeeksforGeeks — What Happens When You Type a URL The direct answer to the question that gets asked almost verbatim — DNS → TCP → TLS → HTTP → render, step by step.
