HLD — distributed systems design

At senior/staff level, HLD is less about knowing every building block and more about defending trade-offs under pressure — why this consistency model, why this partitioning scheme, why not just cache it. The strongest signal an interviewer gets is a candidate who commits to a decision, states the trade-off out loud, and can defend it when pushed, rather than one who lists every option and hedges. This page is the framework, the building blocks, the deep-dive topics organized the way real interviews probe them, and the resources worth working through end to end.

Framework

The 8-step approach

Run every problem through this sequence out loud — interviewers are grading the process at least as much as the final diagram.

1

Requirements

Functional + non-functional. Explicitly ask what's out of scope — a scoped-down design done well beats an unscoped one done poorly.

2

Estimation

Back-of-envelope QPS, storage, and bandwidth. Round numbers, show the math, and use the results to justify later decisions.

3

API design

Core endpoints/contracts. Keep it minimal — just enough to anchor the data model and high-level flow.

4

Data model

Entities, relationships, and the SQL-vs-NoSQL call — justified by the access patterns from step 1, not by default habit.

5

High-level architecture

The boxes-and-arrows diagram: clients, load balancers, services, caches, queues, stores.

6

Deep dive

Interviewer picks 1–2 components to go deep on. This is where the "senior" signal actually gets measured.

7

Stress test

Bottlenecks, single points of failure, hot partitions — proactively surface them before being asked.

8

Wrap-up

Summarize trade-offs made and what you'd revisit with more time. Shows self-awareness about the design's limits.

Building blocks

Breadth pass

You should be able to explain what each of these is, when to reach for it, and its single biggest trade-off in one breath.

Load balancers CDN DNS SQL vs NoSQL Caching (client/CDN/app/DB) Message queues Object storage Search (inverted index) Rate limiting Consistent hashing API Gateway Service discovery Sharding/partitioning Replication Protocols (HTTP/gRPC/WebSocket) Observability Idempotency Backpressure
•CAP theorem and PACELC — and, critically, when not to invoke CAP (don't apply it to a single-node system, a mistake that reads as memorized-not-understood).
•Consistency models: strong, eventual, causal, read-your-writes.
•Consensus: Raft and Paxos at the level of "what problem do they solve and why is leader election hard," not full proofs.
•Partitioning/sharding strategies, distributed transactions (2PC, Saga pattern).
•Storage engines: B-tree vs LSM-tree — why Cassandra/RocksDB pick LSM for write-heavy workloads.
•Caching strategies: cache-aside, write-through, write-behind, and eviction policy trade-offs.
•Kafka internals: partitions, consumer groups, offset management, exactly-once semantics.
•Indexing/search (inverted index basics), time-series aggregation, geospatial indexing (geohash, quadtree).
•Failure handling: retries with backoff, circuit breakers, bulkheads — see the Spring Boot resilience section for implementation depth.
•Rate limiting algorithms (token bucket, sliding window log), networking basics — see the Computer Networks page.
•Real-time delivery (long polling, SSE, WebSocket), distributed ID generation (Snowflake-style).
•Multi-region architecture, observability (metrics/logs/traces), security basics, cost awareness at scale.

Best HLD resources

Free · Primary spine Hello Interview — System Design in a Hurry Built by former FAANG hiring managers. The fastest path to interview-ready if you have limited time — problem breakdowns plus the core-concepts reference used elsewhere on this page. Free + Paid ByteByteGo — Alex Xu Digital companion to "System Design Interview: An Insider's Guide" — clean diagrams, weekly newsletter on real production architectures. Free · Part 1/3 System Design Concepts (1–38) Scalability, availability, reliability, latency vs throughput, client-server, SQL vs NoSQL — the vocabulary layer everything else builds on. Free · Part 2/3 System Design Core Concepts (39–76) WebSockets, API gateways, distributed caches, consensus (Paxos/Raft), 2PC/Saga, CDC — the mid-tier vocabulary most breadth lists skip. Free · Part 3/3 System Design Fundamentals (77–114) Webhooks, WebRTC, CQRS, event sourcing, service discovery, circuit breakers — the advanced-pattern layer that separates senior answers from mid-level ones. Free · 300k★ repo system-design-primer The original open-source breadth reference — index cards on every building block plus worked example architectures. Free · Grad course MIT 6.5840 — Distributed Systems For the "why" behind Raft, MapReduce, and distributed transactions — go here when you want to actually understand consensus, not just cite it.

Also essential as books: Designing Data-Intensive Applications (Kleppmann) and System Design Interview Vol. 1/2 (Xu). Both are the print backbone most of the sites above summarize.
